## 주의할 점
- 사용자는 비전문가다. 용어를 쉽게 풀고 콘솔 작업은 한 화면씩 안내한다. 스크린샷을 받아 확인하는 방식이 잘 통했다.
- DB를 바꾸는 SQL은 내용을 먼저 보여 주고 승인받는다. 지금 Supabase MCP는 실제 DB에 쓸 수 있다. 권한 시험은 `begin; ... set local role authenticated; ... rollback;`에 임시 표로 결과를 모으는 방식이 동작함
- 되돌릴 수 없는 삭제(휴지통 비우기, 영구 삭제, 일정과 문의 삭제)는 대신 실행하지 않는다.
- 개인정보는 개수로만 조회한다. 비밀 키는 채팅으로 받지 않는다. 공개 저장소라 실제 이름, 학번, 토큰을 문서와 커밋에 넣지 않는다.
- 초대 링크는 7일 동안 여러 번 쓸 수 있다. 쓰고 나면 멤버 화면에서 취소한다.
- 앱 안 브라우저 창은 localhost에서 내보낸 두 번째 계정으로 로그인돼 있어 `초대가 필요합니다`만 보인다. 관리자 화면은 사용자 Chrome에서 사용자가 로그인한 뒤 확인했다.
- Liveblocks 운영 키를 Roll하면 앱이 끊긴다. Roll하면 Vercel과 백업 저장소를 함께 바꾸고 재배포한다.
- 승인된 도메인의 supabase 항목을 지우면 로그인이 깨질 수 있다. 브랜딩에 로고를 올리면 검토가 시작될 수 있다 (추측).
- 시험하지 않은 것: 배포 주소에서 실제 영구 삭제, 멤버 화면에서 영구 삭제 버튼 숨김(코드로만 확인), 좁은 화면의 휴지통 버튼, 테스트 사용자 목록에 없던 계정의 로그인, 휴지통 30일 자동 삭제, CSP
- 영구 삭제나 30일 자동 삭제를 해도 Liveblocks 방과 백업에는 내용이 남는다.
- 남은 틈: 멤버가 자기 탭의 상위 탭이나 일정 연결 탭을 숨은 캡처 탭으로 지정 가능 (탭 번호를 알아야 함, 막지 않음)

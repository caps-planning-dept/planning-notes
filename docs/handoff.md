## 주의할 점
- DB를 바꾸는 SQL은 내용을 먼저 보여 주고 승인받은 뒤 실행한다. 이전 마이그레이션은 다시 실행하지 않는다.
- 지금 Supabase MCP는 실제 DB에 쓸 수 있다.
- 시험은 가짜 정보로 하고, 개인정보는 개수로만 조회한다. 신청 링크 토큰은 문서에 적지 않는다.
- 끝에서 되돌리는 임시 DB 시험은 사용자가 승인하지 않아 실행하지 않았다. 다시 시도하려면 먼저 묻는다.
- 아직 실제 동작을 시험하지 않은 것: 긴 이름 가입, 하위 탭 함께 삭제, 내보낼 때 열람 권한 삭제, 분당 신청 제한, 일반 멤버와 로그인 안 한 사용자의 실제 권한, 로그인 없이 신청 제출, 권한 회수 후 새 표의 자동 RLS
- 화면에서 눌러 보지 않은 것: 활동 칸 초기화, 신청 삭제 시 조 삭제, 지운 날짜의 조 수정, 좁은 화면의 답글, 답글 수정·삭제·해결, 실제 휴대폰
- 신청 폼 빈 화면 문제(개발 서버 재시작으로 해결)는 원인을 찾지 못했다.
- 남은 시험 데이터: 휴지통의 탭 3개, 시험 문의 1건, Liveblocks의 `devtest:collab` 방과 `기능 시험` 노트의 답글
- `캡처 시즌2`는 신청이 열려 있고 날짜가 없다. 실제 회차인지 시험 회차인지 확인하지 못했다.
- `.mcp.json`은 공개 저장소에 넣을지 정하지 않았다.

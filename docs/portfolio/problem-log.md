# 문제 해결 기록

개발 중 만난 문제를 증상, 원인, 해결, 확인 순서로 남깁니다.

## 2026-11-05: 답글을 단 글의 글씨 색이 사라짐

- **증상:** 글씨 색을 빨강으로 지정했는데 답글이 달린 문장은 검게 보였다. 도구 막대의 글씨 색 버튼은 켜져 있었다.
- **원인:** Liveblocks의 답글 표시 태그가 자체 글자색을 지정해, 그 바깥에 적용된 빨강을 덮어썼다. 브라우저에서 각 태그의 계산된 색을 비교해 확인했다.
- **해결:** 노트 안의 답글 표시는 바깥 글씨 색과 굵기를 그대로 따르도록 스타일을 추가했다.
- **확인:** 같은 문장이 답글 표시를 유지한 채 빨강으로 보이는 것을 화면에서 확인했다.

## 2026-11-05: 답글 버튼이 도구 막대를 가림

- **증상:** 첫 줄을 선택하면 답글 버튼이 처음에는 도구 막대 뒤로 숨었고, 앞으로 가져오자 이번에는 굵게 버튼 등을 가렸다.
- **원인:** 버튼이 선택한 글 위쪽에 뜨는데 첫 줄 위에는 도구 막대가 있다.
- **해결:** 버튼의 표시 순서를 올리고, 본문 위쪽에 자리가 없으면 글 아래에 띄우도록 했다.
- **확인:** 첫 줄을 선택했을 때 버튼이 글 아래에 뜨고 도구 막대가 가려지지 않는 것을 확인했다.

## 2026-11-05: DB에는 적용됐지만 마이그레이션 기록이 없음

- **증상:** 조장 SQL의 새 열은 실제 DB에 있는데, 마이그레이션 적용 기록은 0건이다. 저장소의 SQL 파일 4개 모두 기록이 없다.
- **원인:** SQL을 기록에 남지 않는 방식(예: Supabase SQL 편집기)으로 실행한 것으로 추정한다. 실제 실행 방식은 확인하지 못했다.
- **위험:** 앱 동작에는 문제가 없지만, 이 상태로 `supabase db push` 같은 명령을 쓰면 이미 적용한 SQL을 처음 실행하는 것으로 착각해 오류가 나거나 다시 실행될 수 있다.
- **해결:** SQL은 다시 실행하지 않고, 기록 표에 이전 SQL 4개를 적용됨으로 추가했다. 이후 DB 변경은 Supabase MCP로 적용해 기록이 자동으로 남게 했다.
- **확인:** 기록 목록에 저장소의 SQL 파일 6개가 모두 나오는 것을 확인했다. `supabase db push`로 실제 비교해 보지는 않았다 (CLI 미설치).

## 2026-11-05: 시험 중 캡처 신청 폼이 빈 화면으로 보임

- **증상:** 신청을 한 건 제출한 뒤 다시 연 신청 폼이 빈 화면으로 나왔고, 다시 불러와도 같았다.
- **원인:** 개발 서버 로그에 `/apply/[token]` 경로를 준비하는 보조 프로세스가 반복해서 죽었다는 `Jest worker` 오류가 있었다. 왜 죽었는지는 찾지 못했다. 서버가 오래 켜져 있었고 여유 메모리가 약 2GB였지만, 이것이 원인인지는 확인하지 못했다.
- **해결:** 코드는 고치지 않고 개발 서버를 다시 켰다.
- **확인:** 다시 켠 뒤 신청 폼 제출, 조 편성, 이미지 저장까지 같은 오류 없이 진행했다. 배포용 빌드에서 재현되는지는 확인하지 않았다.

## 2026-11-05: 접속자는 보이는데 노트 내용이 동기화되지 않음

- **증상:** 두 창에서 서로의 접속은 표시되지만 글이 전달되지 않고, 새로고침하면 내용이 사라졌다.
- **원인:** 방 연결이 끝나기 전에 편집기를 만들어 편집기가 실제 공유 문서와 연결되지 않은 것으로 판단했다. 서버 문서를 조회해 본문이 전혀 저장되지 않았음을 확인했다.
- **해결:** 공식 예제처럼 `ClientSideSuspense`로 방 연결 뒤에 편집기를 만들고, 첫 내용은 한 번만 넘기도록 고정했다.
- **확인:** 임시 시험 페이지의 두 탭에서 입력이 바로 전달되고, 서버 문서에 본문이 저장되며, 새로고침 후에도 남는 것을 확인했다.

## 2026-11-05: 테스트 도구 설치 실패

- **증상:** `npm i -D vitest`가 의존성 충돌 오류로 실패했다.
- **원인:** Vitest 5는 `@types/node` 22 이상을 요구하는데, 프로젝트 기본값은 20이었다.
- **해결:** `--force`로 무시하지 않고, 설치된 Node.js 24에 맞춰 `@types/node`를 24로 올렸다.
- **확인:** `npm test`로 테스트 14개가 통과했다.

## 2026-11-05: 깎인 모서리에서 키보드 포커스 표시가 잘릴 수 있음

- **증상:** `clip-path`로 모양을 자르면 요소 바깥에 그리는 포커스 표시도 함께 잘린다.
- **원인:** `clip-path` 영역 밖의 내용은 그려지지 않는다.
- **해결:** 해당 요소는 `outline-offset`을 음수로 설정해 표시를 안쪽에 그렸다.
- **확인:** 코드와 규칙에 반영했다. 키보드만으로 전체 화면을 확인하는 점검은 아직 하지 않았다.

## 2026-11-05: 달력의 빈 칸이 너무 진하게 보임

- **증상:** 다른 달에 해당하는 빈 칸이 진한 회색으로 보여 시선을 빼앗았다.
- **원인:** 반투명 배경 뒤로 격자선 색이 비쳤다.
- **해결:** 불투명한 연한 배경 토큰으로 바꿨다.
- **확인:** 브라우저 화면에서 확인했다.

## 2026-11-06: 새 노트를 만들면 동시 편집 입장 오류가 남

- **증상:** 일반 노트를 만들 때 `Liveblocks Authentication failed: Forbidden` 오류가 났다. 같은 조건에서 다시 만들어 재현했다.
- **원인:** 화면이 DB 저장보다 먼저 새 노트를 열어, 입장 권한 확인 때 아직 탭을 찾지 못했다.
- **해결:** 저장이 끝난 뒤 탭을 열고, 저장에 실패하면 목록에서 뺀다.
- **확인:** 수정 후 새 노트를 만들었을 때 오류가 없었다.

## 2026-11-06: 다른 사람이 탭을 만들면 보던 화면이 넘어감

- **증상:** 관리자가 새 탭을 만들자 멤버 화면이 그 탭으로 바뀌었다. 시험 중 멤버 창의 사이드바에서 발견했다.
- **원인:** 직접 탭을 고르지 않으면 항상 "목록의 첫 탭"을 보여 줘, 첫 탭이 바뀌면 화면도 따라 바뀌었다.
- **해결:** 처음 연 탭을 고정한다.
- **확인:** 멤버가 다른 노트를 보는 동안 관리자가 새 탭을 만들어도 화면이 그대로였다.

## 2026-11-06: 다른 사람이 지운 탭이 화면에 남음

- **증상:** 멤버가 지운 탭의 설정 화면을 관리자가 계속 보고 수정할 수 있는 상태였다. 지워진 탭을 숨기자 이번에는 탭이 있는데도 `첫 탭을 만들어 보세요`가 나왔다.
- **원인:** 보던 탭이 휴지통에 갔는지 확인하지 않았다.
- **해결:** 보던 탭이 지워지면 남아 있는 첫 탭으로 옮긴다.
- **확인:** 관리자가 시험 탭을 지웠을 때 그 탭을 보던 멤버 화면이 다음 노트로 옮겨 갔다.

## 2026-11-06: 이름을 바꿔도 새로고침 전에는 그대로임

- **증상:** 개발 담당자가 시험 중 발견했다. 커서와 답글, 함께 편집 표시에 이전 이름이 남았다.
- **원인:** 커서 이름은 노트 입장 권한에 담겨 한 번만 전달되고, 답글 이름은 Liveblocks가 저장해 두고 다시 쓴다.
- **해결:** 내 이름이 바뀌면 노트에 다시 입장하고, 답글 이름을 다시 찾게 했다. 입장 권한이 DB의 이름을 읽으므로 DB 저장이 끝난 뒤에 화면을 바꾼다.
- **확인:** 양쪽 창에서 새로고침 없이 바뀌는 것을 확인했다.

## 2026-11-06: 함께 편집 표시에 같은 이름이 두 번 나옴

- **증상:** `관리자, 관리자 외 1명 함께 편집 중`처럼 같은 사람의 이름이 두 번 나왔다.
- **원인:** 사람 수가 아니라 열린 탭(연결) 수를 셌다.
- **해결:** 같은 사람은 한 번만 세고, 내 다른 탭은 빼고, 이름은 멤버 목록에서 읽는다.
- **확인:** 관리자 탭이 여러 개인 상태에서 이름이 한 번만 나왔다.

## 2026-11-06: 좁은 화면에서 답글이 안 보이고 입력창이 잘림

- **증상:** 개발 담당자가 발견했다. 좁은 화면에서는 답글이 보이지 않았고, 답글 입력창이 사이드바에 가려졌다. 시험 중 입력창 틀이 좁은 화면 밖으로 나가는 것도 추가로 찾았다.
- **원인:** 좁은 화면의 답글은 표시된 글을 눌러야만 떴다. 입력창이 사이드바보다 아래 층에 있었고, 라이브러리 기본 너비가 350px로 고정되어 있었다.
- **해결:** 좁은 화면에서는 본문 아래에 답글을 모아 보여 준다. 입력창을 사이드바 위로 올리고 너비를 화면에 맞춘다.
- **확인:** 너비 332px에서 입력창이 왼쪽 10px, 오른쪽 310px 위치로 화면 안에 들어왔다.

## 2026-11-06: 공개될 문서에 실제 이름을 적음

- **증상:** 배포 전 점검에서 문제 기록의 예시 문구에 실제 이름이 들어간 것을 찾았다.
- **원인:** 화면에 보인 문구를 그대로 옮겨 적었다.
- **해결:** 문구를 `관리자`로 바꿨다. 이전 커밋 기록에는 남아 있어 공개 전에 처리해야 한다.
- **확인:** 현재 파일에서 실제 이름과 이메일 검색 결과가 없다.

## 2026-11-06: 내보낸 멤버의 화면이 그대로 남음

- **증상:** 내보내도 새로고침 전까지 탭 목록과 불러온 내용이 보였다.
- **원인:** 멤버 목록이 바뀌어도 내가 빠졌는지 확인하지 않았다.
- **해결:** 멤버 목록에서 내가 사라지면 첫 주소로 다시 이동해 초대 안내를 보여 준다.
- **확인:** 멤버 창을 열어 둔 채 내보내자 새로고침 없이 초대 안내로 바뀌었다.

## 2026-11-06: 첫 자동 백업이 권한 오류로 실패

- **증상:** 백업 작업이 `permission denied for table workspaces`로 멈췄다.
- **원인:** 새 표를 자동으로 공개하지 않는 설정이라 `service_role`에도 표 권한이 없었다. `service_role`은 원래 모든 표를 읽을 수 있다고 잘못 가정했다.
- **해결:** 백업 대상 표의 읽기 권한만 주고, 프로필은 표시 이름 칸만 열었다. 캡처 표는 열지 않았다.
- **확인:** 권한 조회와 재실행으로 확인했다. 백업된 개수가 DB 개수와 같았다.

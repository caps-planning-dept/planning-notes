# 시험 기록

직접 실행해 확인한 시험의 절차와 결과를 남깁니다. 실행하지 않은 항목은 `시험하지 않은 것`에 따로 적습니다.

## 2026-11-05: 코드 리뷰와 보안 점검 후 수정 확인

Claude가 브랜치 전체를 코드 리뷰하고 보안 항목을 직접 점검했다. `security-review` 스킬은 GitHub 원격 저장소가 없어 실행되지 않아, 같은 범위를 수동으로 확인했다.

### 점검 결과

| 항목 | 결과 |
|---|---|
| 코드 리뷰 | 문제 10건 찾아 모두 수정 |
| Git 기록의 비밀 키 | 없음 (패턴 검색에서 잡힌 1건은 설정 파일의 설명 문구) |
| 의존성 취약점 | 높음·치명 없음. 남은 보통·낮음 6건은 `shadcn` 명령줄 도구 쪽이며 강제 업데이트가 필요해 보류 |
| Supabase 점검 도구 | 외부 호출 대상으로 열려 있던 내부 함수 1건을 닫음. 남은 경고는 의도한 공개 함수 3건과, Google 로그인만 써서 해당 없는 비밀번호 유출 검사 |

### 확인 방법

| 수정 | 결과 | 확인 방법 |
|---|---|---|
| 탭 수정 칸 제한 | 통과 | 권한 조회, 앱에서 캡처 탭 생성·이름 변경·고정·삭제 |
| 초대 링크 목록과 취소 | 통과 | 앱에서 링크 생성 후 목록 확인, 취소 후 목록에서 사라짐 |
| 보안 헤더 | 통과 | 응답 헤더 확인 |
| 로그인 없는 신청 폼 접근 | 통과 | 로그인 정보 없는 요청으로 페이지 응답 확인 (없는 링크 주소로 확인) |
| 조 중복 방지 | 통과 | 자동 테스트 |
| 자동 검사 | 통과 | 타입 검사, 린트, 테스트 72개, 배포용 빌드 |

### 시험하지 않은 것

- **트리거와 제한의 실제 동작:** 가입 이름 처리, 하위 탭 삭제 연쇄, 멤버 제거 시 열람 권한 삭제, 분당 제한은 DB에 설치된 것만 조회로 확인했다. 되돌리는 임시 시험을 제안했으나 승인되지 않아 실행하지 않았다.
- **일반 멤버와 로그인 안 한 사용자의 실제 권한:** 권한 설정을 조회만 했다. 두 번째 계정으로 확인해야 한다.
- **화면 수정 일부:** 활동 칸 초기화, 신청 삭제 시 조 삭제, 삭제한 날짜의 조 수정은 화면에서 눌러 보지 않았다.
- **자동 RLS:** 권한 회수 후 새 표에 RLS가 자동으로 켜지는지 확인하지 않았다.

## 2026-11-05: 캡처 기능 전체 흐름

### 환경

- 내 컴퓨터의 개발 서버(`localhost:3000`)와 크롬 브라우저
- 실제 Supabase 프로젝트에 새로 만든 `캡처 시험` 회차 (12/1, 12/2)
- 가짜 신청자 3명: `시험일`, `시험이`, `시험삼` (학번은 `999`로 시작하는 가짜 값)

### 시험 전 DB 확인

DB를 수정하지 않고 조회만 했으며, 개인정보를 보지 않도록 개수만 확인했습니다.

| 확인 항목 | 결과 |
|---|---|
| 조장 SQL의 마이그레이션 기록 | 없음. 저장소의 4개 파일 모두 기록이 없음. [문제 기록](problem-log.md) 참고 |
| 기존 조의 조장 값 | 2개 조 모두 채워져 있음 |
| 신청 함수의 동의 확인 | 남아 있지 않음 |

### 결과

| 단계 | 결과 | 확인 방법 |
|---|---|---|
| 신청 폼 제출 | 통과 | 3건 제출 후 신청 현황 화면에서 3명과 날짜별·활동별 인원 확인 |
| 조 만들기 | 통과 | 1조(12/1, 보드게임, 메모 `음주 X`, 3명) 화면과 DB 확인 |
| 조장 변경 | 통과 | 기본 조장 `시험일`을 `시험이`로 변경 후 화면과 DB 확인 |
| 새로고침 후 유지 | 통과 | 새로고침 후 조, 메모, 조장 확인 |
| 이미지 저장 | 통과 | 내려받은 파일을 직접 열어 날짜, 활동, 조, 메모, 이름이 있고 학번이 없음을 확인 |

저장한 이미지: [capture-test-board.png](../design/capture-test-board.png)

### 시험 중 발견한 것

- 시험 도중 신청 폼이 빈 화면으로 나와 개발 서버를 다시 켰다. [문제 기록](problem-log.md) 참고
- 이미지에는 요구사항의 5개 항목 외에 회차 제목, CAPS 로고, `조장` 표시도 들어간다. 개인정보는 아니며, 아직 문서나 화면을 바꾸지 않았다.
- 화면 낭독기용 안내가 `시험이을 조장으로 지정`처럼 나온다. 아직 고치지 않았다.

### 시험하지 않은 것

- 휴대폰 화면
- 다른 계정으로 초대와 동시 편집
- 배포용 빌드와 배포된 환경
- 휴지통으로 옮긴 회차의 신청 링크 거부 (함수 코드로만 확인)

첫 번째 신청은 실제 클릭으로 진행했다. 2, 3번째 신청의 선택과 제출, 조원 선택, 조장 변경은 화면의 버튼을 스크립트로 눌렀다.

### 시험 후 정리

앱 화면에서 가짜 신청 3건을 삭제하고 `캡처 시험` 탭을 휴지통으로 옮겼다. 이름 없는 조 기록 1개는 탭과 함께 휴지통에 남아 있다. DB 조회로 다른 회차의 신청과 조 개수가 그대로임을 확인했다.

### 역할

- **개발 담당자:** 확인 항목과 시험 순서 결정, Google 로그인, 시험 회차·커밋·서버 재시작·데이터 정리 승인
- **Claude:** DB 조회, 브라우저 시험 실행, 결과 확인, 이 기록 작성

| 두 창의 동시 편집, 커서 표시 | 통과 |

자동 검사: 타입 검사, 린트, 테스트 72개, 배포용 빌드 통과.

### 시험 중 발견하고 고친 것

[문제 기록](problem-log.md)에 원인과 해결을 적었다: 새 노트 입장 오류, 다른 사람이 만든 탭으로 화면이 넘어감, 지워진 탭이 화면에 남음, 이름 반영 지연, 함께 편집 표시 중복, 좁은 화면 답글, 답글 입력창 잘림.

### 아직 남은 것

- 휴지통에서 복원했을 때 신청 폼 상태는 시험하지 않았다. 지운 회차의 `열림` 값은 DB에 그대로 남아 있어, 복원하면 폼이 다시 열릴 것으로 추측한다.
- 실제 휴대폰, 로그인 안 한 사용자의 신청 제출, 배포된 환경은 시험하지 않았다.

### 역할

- **개발 담당자:** 시험 범위와 데이터 변경 승인, Google 로그인, 멤버 화면 확인, 화면 문제 발견
- **Claude:** 원인 분석과 수정, 브라우저 시험 실행, DB 개수 조회, 이 기록 작성

- 내보낸 뒤 이미 받은 Liveblocks 입장 권한이 언제까지 유효한지
- 배포된 환경의 보안 헤더와 CSP

## 2026-11-06: 일반 멤버의 쓰기 시도

DB 안에서 일반 멤버 계정의 로그인 정보를 흉내 내어 쓰기를 시도하고, 시도마다 마지막에 취소(rollback)했다. 막히지 않은 시도도 실제 데이터에는 남지 않는다. 같은 시도를 관리자로도 실행해, 대상이 실제로 있는데 멤버만 막히는지 확인했다.

| 시도 | 멤버 | 관리자 |
|---|---|---|
| 자기 역할을 관리자로 올리기, 관리자 내보내기, 관리자 이름 바꾸기 | 0건 반영 | 해당 없음 |
| 초대 링크 만들기, 캡처 탭 만들기 | 거부 | 해당 없음 |
| 탭 종류 바꾸기 | 거부 (칸 권한 없음) | 해당 없음 |
| 숨은 캡처 탭 수정·휴지통, 신청 폼 열고 닫기 | 0건 반영 | 1건 반영 |
| 자기를 캡처 열람자로 추가 | 거부 | 성공 |
| 신청 삭제 / 신청 직접 넣기 | 0건 반영 / 거부 | 1건 반영 / 시험 안 함 |
| 조 만들기·수정 | 거부, 0건 반영 | 성공 |
| 남의 이름으로 문의 쓰기 / 문의 상태 바꾸기 | 거부 / 0건 반영 | 해당 없음 |
| 숨은 캡처 탭에 노트·일정 쓰기 | **처음엔 성공**, 수정 후 거부 | 성공 |

마지막 항목은 [문제 기록](problem-log.md)에 적고 고쳤다. 수정 후에도 멤버가 일반 노트와 일정 탭에 쓰는 것은 성공했다.

첫 실행에서는 휴지통 밖에 캡처 탭이 없어 캡처 관련 시도가 빈 대상으로 실행됐다. 결과를 그대로 믿지 않고 휴지통의 캡처 탭으로 다시 실행했다.

### 시험하지 않은 것

- 실제 앱 화면이나 API 주소를 거친 요청. DB 권한만 확인했다.
- 멤버가 자기 탭의 상위 탭이나 일정의 연결 탭을 숨은 캡처 탭으로 지정하는 것. 탭 고유 번호를 알아야 하며 막는 규칙은 없다.

## 2026-11-06: 배포 주소에서 로그인 없이 신청 제출

관리자는 Chrome, 신청자는 로그인 정보(쿠키, 저장소)가 하나도 없는 앱 안 브라우저 창에서 `https://caps-planning.vercel.app`으로 시험했다. 시험 전에 두 번째 계정을 관리자 화면에서 내보냈다(멤버 1명, 캡처 열람자 0건 확인).

| 단계 | 결과 |
|---|---|
| 관리자가 캡처 탭 `배포 신청 시험`을 만들고 날짜 12/20 추가, 신청 열기 | 통과 |
| 로그인 없이 신청 폼 열기, 가짜 값(학번 `999` 시작)으로 제출 | 통과, `신청했습니다` 표시 |
| 관리자 신청 현황 | 신청자 1명, 12/20 1명, 보드게임 1명 |
| 신청을 닫은 뒤 폼 다시 열기 | `신청을 받고 있지 않습니다` |

### 시험 후 정리

설정의 `신청 내용 모두 삭제`로 가짜 신청 1건을 지우고 탭을 휴지통으로 옮겼다. DB 조회로 남은 신청 0건, 열린 회차 0개를 확인했다.

### 시험 중 본 것

- 탭을 휴지통으로 옮기자 첫 화면이 아니라 사이드바의 다음 탭(`1`)이 열렸다. 의도한 동작인지는 정하지 않았다.

- **배경:** 열람자 설정은 캡처 탭에만 있었다. 기획 중인 내용처럼 일부 멤버만 봐야 하는 노트·일정도 모든 멤버에게 보였다.
- **결정(사용자 선택):** 모든 탭에 `모든 멤버 / 지정한 멤버만`을 둔다. 바꾸는 사람은 관리자와 `설정 가능`인 멤버(처음에는 탭을 만든 사람)다. 상위 탭을 볼 수 없으면 하위 탭도 볼 수 없다. 볼 수 없는 멤버에게는 탭이 아예 보이지 않는다. 누구나 자기를 열람자에서 뺄 수 있지만, 관리자가 아닌 마지막 설정 가능자는 다른 멤버에게 설정 권한을 넘긴 뒤에 빠진다. 관리자는 언제나 모든 탭을 본다.
- **캡처 탭:** 학번이 있어 언제나 `지정한 멤버만`이고 열람자는 관리자만 바꾼다. 따로 있던 `capture_viewers` 표는 새 `tab_viewers` 표로 옮기고 지웠다.
- **DB:** 탭을 볼 수 있는지는 `private.can_see_tab` 하나로 판단한다. 노트·일정·시간표·첨부 파일·캡처·노트 동시 편집 입장이 모두 이 기준을 따른다. "마지막 설정 가능자" 규칙은 화면뿐 아니라 DB 트리거로도 막는다.
- **시험에서 바꾼 것:** 빈 Postgres(PGlite)에 마이그레이션을 돌려 36개 경우를 시험했다. 새 탭을 만들고 같은 문장에서 돌려받으면 탭 보기 정책이 방금 만든 행을 찾지 못해 실패해서, 자기 행은 행의 값으로 직접 확인하게 바꿨다.
- **대안:** 이름만 보이고 잠긴 탭(제목이 새어 나감), 하위 탭을 상위와 따로 설정(사이드바에 부모 없는 탭이 생김)은 쓰지 않았다.

## 2026-11-10: 관리자도 열람자에서 뺄 수 있게 함

- **배경:** 처음에는 관리자가 언제나 모든 탭을 봤다. 사용자가 관리자의 열람 권한도 지울 수 있기를 원했다.
- **결정:** `지정한 멤버만`인 탭은 관리자도 체크되어 있어야 본다. 관리자는 볼 수 있는 탭의 설정은 여전히 바꾼다. 적용 직후 보이던 탭이 사라지지 않게, 이미 `지정한 멤버만`인 탭에는 모든 관리자를 열람자로 넣었다. 탭을 `지정한 멤버만`으로 바꾸는 사람은 자동으로 열람자가 된다.
- **아무도 못 보는 탭 막기:** `지정한 멤버만`인 탭의 마지막 설정 가능자(관리자 포함)는 다른 사람에게 넘긴 뒤에만 빠진다. 캡처 탭은 다른 관리자를 열람자로 넣는 것이 넘기기다.
- **시험에서 바꾼 것:** 빈 Postgres에서 두 마이그레이션을 차례로 돌려 57개 경우를 시험했다. (1) 관리자가 열람자가 아닌 남의 탭을 `지정한 멤버만`으로 바꾸면, 한 문장 안에서 넣은 열람자 줄을 탭 보기 정책이 보지 못해 막혔다. 열람자를 먼저 넣고 다음 문장에서 바꾸는 DB 함수 `set_tab_viewers_only`로 바꿨다. (2) 관리자가 캡처 탭을 만들고 바로 돌려받을 때 만든 사람 줄이 아직 없어 막혀서, 열람자가 하나도 없는 새 탭은 만든 사람이 볼 수 있게 했다.
